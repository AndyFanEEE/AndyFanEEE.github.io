基于 1D-CNN 的 SQL 注入检测系统实现：从规则匹配到深度学习

May 10, 2026
阅读时长: 8 分钟

前言

毕竟是学网安的，也算学了点web安全方面的内容，刚好最近有课程项目作业是训练个模型来进行身份认证，我就想能不能训练个模型来拦截sql注入攻击，于是我决定用深度学习来搞，在Kaggle找了三万条真实SQL数据，参考网上资料并结合ai搭建了个1D-CNN模型让它自己学攻击特征。

项目概述

输入一条 SQL 语句，系统判断它是正常请求还是注入攻击，输出攻击概率（0~1）和风险等级（安全 / 中危 / 高危）。不写规则，让模型从数据里自己学。

和传统方案的核心区别

正则规则匹配（传统 WAF） 本方案（1D-CNN）
检测方式 人工维护关键词黑名单 模型自动学习攻击特征
对变形攻击 SeLeCt、/**/ 轻松绕过 字符级建模，变形影响小
新型攻击 需要手动更新规则 重新训练即可覆盖
误报率 高（正常 SQL 含关键词也触发） 低（实测误报仅 3/3853）

背景知识

SQL 注入的主要类型

布尔盲注：构造恒真或恒假条件，通过页面返回是否变化来探测漏洞。

1
2
3
4
5

-- 恒真，WHERE 条件失效，返回表里所有数据
1' OR '1'='1' --

-- 恒假，页面返回空，和上面对比确认注入点存在
1' AND '1'='2' --

-- 是 SQL 注释符，把后面所有内容（包括密码验证）全部截断。

联合注入：用 UNION 把额外的查询结果拼到正常返回里一起输出。

1

' UNION SELECT username, password FROM users --

页面原本只显示商品名，注入后连 users 表的账号密码一起带出来。

堆叠注入：用分号 ; 在一次请求里塞多条语句，破坏性最强。

1

'; DROP TABLE users; --

第一条正常执行，第二条直接删表，数据永久丢失。

时间盲注：不返回额外数据，通过让数据库延时响应来确认漏洞。

1

1' AND SLEEP(5) --

页面 5 秒后才响应说明注入成功，攻击者用这个方法逐位猜出数据内容。

SQL 注入的概率是怎么算出来的

拿 1' OR '1'='1' -- 走一遍完整计算过程：

Step 1：Tokenizer 分词 输入字符串 → [1, 23, 156, 89, 45, 12, ...]（填充到长度 128）

Step 2：Embedding 层 [1, 23, 156, ...] → 128 × 64 的浮点矩阵（每个词变成 64 维向量）

Step 3：Conv1D 卷积核滑动扫描 发现 [OR, '1', =] 组合权重很高 → 激活值大

Step 4：MaxPooling → Flatten → Dense 提取关键特征，输出标量 z = 3.82

Step 5：Sigmoid 函数

$$P = \frac{1}{1 + e^{-3.82}} = 0.9785$$

输出攻击概率 97.9%，标记高危。风险等级按概率区间划分：

概率范围 风险等级
< 0.5 ✓ 安全
0.5 ~ 0.8 ⚠ 中危
≥ 0.8 ⚠ 高危

关键公式：Sigmoid 激活函数

$$ P(\text{攻击}) = \sigma(z) = \frac{1}{1 + e^{-z}} $$

其中 $z$ 是最后一层全连接层的输出，$\sigma(z)$ 把任意实数压缩到 [0, 1] 区间，表示攻击概率。当 $z=3.82$ 时，$P=0.9785$，即 97.9% 的概率是攻击。

2. 文本向量化

SQL语句是字符串，神经网络只吃数字，所以得先把字符串变成数字序列。

第一步：Tokenizer 分词 + 序列化

把每个词映射成整数编号，词典上限2000，足够装下所有 SQL 关键词和常见词汇：

1
2
3

tokenizer = Tokenizer(num_words=MAX_WORDS, oov_token='<OOV>')
tokenizer.fit_on_texts(df['query'])
sequences = tokenizer.texts_to_sequences(df['query'])

oov_token='<OOV>' 处理词典外的词，演示时输入新语句不会崩。效果如下：

第二步：pad_sequences 统一长度

神经网络要求输入维度固定，统一填充到 128：

短的在后面补 0，超过 128 的从后截断。每条语句最终变成长度 128 的整数数组。

inputs = Input(shape=(MAX_LEN,), name='sql_input')

# 词嵌入：整数编号 → 64 维连续向量
x = Embedding(input_dim=MAX_WORDS, output_dim=EMBED_DIM, name='embedding')(inputs)

# 第一个卷积块：捕捉短词组特征（如 OR 1=1、SLEEP(）
x = Conv1D(filters=128, kernel_size=3, activation='relu', name='conv1')(x)
x = MaxPooling1D(pool_size=2, name='pool1')(x)

# 第二个卷积块：捕捉更高层的组合特征
x = Conv1D(filters=64, kernel_size=3, activation='relu', name='conv2')(x)
x = MaxPooling1D(pool_size=2, name='pool2')(x)

x = Flatten(name='flatten')(x)
x = Dense(64, activation='relu', name='fc1')(x)
x = Dropout(0.3, name='dropout')(x)          # 随机丢弃 30%，防过拟合

# 输出层：Sigmoid 压缩到 [0,1]
outputs = Dense(1, activation='sigmoid', name='output')(x)

model = Model(inputs=inputs, outputs=outputs, name='SQLInjectionCNN')

各层的作用：

Embedding 层：把整数编号转成 64 维浮点向量。语义相近的词（OR、AND）在这个空间里距离更近，比词袋模型更能表达语义。就像把每个词都放到一个 64 维的空间里，意思相近的词会靠得比较近。

Conv1D 层：卷积核大小为 3，每次看 3 个相邻 token 的组合，在整个序列上滑动扫描。UNION SELECT、OR '1'='1'、SLEEP( 这类固定组合就是在这里被捕捉到的。可以想象成一个滑动窗口，在序列上滑动搜索来寻找那些危险的词组组合。

MaxPooling1D 层：每个窗口只保留最大值，降低维度同时保留最显著特征，增强对位置变化的鲁棒性。相当于从一堆特征里挑最强的那个留下。

Dropout 层：训练时随机丢弃 30% 的神经元，避免它过度依赖训练数据，提高对新语句的泛化能力。

Sigmoid 输出：计算攻击概率: $P = \frac{1}{1 + e^{-z}}$，把任意实数 $z$ 压缩到 0~1，超过 0.5 判定为攻击。

重点说一下 EarlyStopping + restore_best_weights=True 这个组合：训练集损失继续降但验证集损失开始回升时自动停止，同时保存的是验证损失最低那轮的权重，不是最后一轮。这个功能特别好用，能有效防止过拟合，不用手动盯着训练曲线。

def detect(sql: str, model, tokenizer) -> dict:
    clean = sql.lower().strip()
    seq = tokenizer.texts_to_sequences([clean])
    pad = pad_sequences(seq, maxlen=MAX_LEN, padding='post', truncating='post')
    prob = float(model.predict(pad, verbose=0)[0][0])

    risk = '高危' if prob >= 0.8 else ('中危' if prob >= THRESHOLD else '安全')
    return {'prob': prob, 'label': 1 if prob >= THRESHOLD else 0, 'risk_level': risk}

踩坑记录

1、CSV 读取报 NaN 转 int 失败

最开始直接 pd.read_csv 后执行 df['label'].astype(int)，结果报错 ValueError: cannot convert float NaN to integer。经过检查发现是数据集格式有问题——CSV 有 4 列，其中 310 行数据向右错位了，SQL 语句跑到了 Label 列，pandas 把无法解析的值填成了NaN。

解决方案：分两种情况处理再合并，Label 列是 0/1 的正常取，Label 列是字符串而第三列是 0/1 的按错位行处理。

2、正常 SQL 语句显示中危或高危

输入 SELECT name, email FROM users WHERE id=5 这条明显正常的查询，模型居然给出中危甚至高危的判定，当时觉得模型有问题。

根本原因：数据集的偏差——该数据集里直接查询 users 表的语句大量被标注为攻击（因为联合注入攻击几乎都会查 users 表），模型学到了这个组合是高风险信号。

处理：这是数据集本身的偏差（Data Bias），属于模型局限性，不影响对真实攻击语句的检测效果。

总结

做得好的地方： 用真实 3 万条数据训练，覆盖 6 种主流注入类型，模型泛化能力有保证；双层卷积结构比单层能捕捉更复杂的词组组合，像 OR '1'='1' 这种经典注入模式基本都能识别；EarlyStopping + restore_best_weights 这个组合真的好用，自动找最优停止点，不用手动盯着训练曲线；数据集的错位行处理完整，一条数据没有丢；三张可视化图表完整覆盖实验数据，AUC 0.9993、召回率 98.8%，这个数字还是挺能打的。

不足之处： 只做了二分类（正常 vs 攻击），没有区分注入类型，不知道是布尔盲注还是联合注入；模型对包含 users 等高频攻击词的正常语句误判率偏高，这是数据集偏差带来的问题，没办法；没有在线更新机制，遇到全新攻击手法需要重新采集数据训练，不够灵活。

后续可以改进的方向：

  • 字符级建模：把 char_level=True 传给 Tokenizer，在字符粒度上学习特征，对大小写混写和注释绕过（比如 S/**/ELECT）的识别能力更强
  • 多分类输出：把标签细化为正常 / 布尔注入 / 联合注入 / 时间盲注 / 堆叠注入，输出层改为多分类 + Softmax，能知道具体是什么类型的攻击
  • 注意力机制：在卷积层后加 Self-Attention，让模型自动关注序列里最重要的位置，对超长复杂 SQL 语句的处理能力更强
