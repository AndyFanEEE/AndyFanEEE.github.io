前言

摆烂了好久，一直没想好第一个文章写什么内容。最终这学期身份认证课程有一个课程项目，刚好能写下给实现过程做个简单的记录。

本项目是课程作业要求根据一篇有关安全认证的论文，复现其认证方法。然后在搜索资料的时候看到了一篇有关“击键动力学”的论文，看了内容感觉难度适合，而且最后复现展示的效果也感觉比较有意思，于是直接就搜集资料开始工作。

项目概述

这个项目是基于击键动力学的身份认证系统，简单来说就是让用户在网页输入框里打一段固定的文字（项目内我们选择输入“hello world”），然后系统会分析该用户的打字节奏来判断这个用户是不是当前登录的用户。

核心功能：

前端采集页面：录入多个用户的打字数据，实时记录用户的按键时间戳

后端特征提取：将原始时间戳转换成31维的特征向量，基于马氏距离与用户模板进行相似度计算，自适应阈值判断是否通过

用户模板构建：用已经录入的数据建立出每个用户的特征模板，用于后续的认证过程

认证界面：计算新输入的数据与模板的相似度，实时判断是否为当前登录的用户

技术栈：

层次选型说明
前端HTML5+原生JS，无框架，PicoCSS界面美化
后端Python+Flask，轻量Web框架，提供API接口
算法NumPy+Scikit-learn，特征处理和归一化
存储每个用户单独一个CSV文件

背景知识：

为什么打字节奏能识别身份

我们平时生活使用电脑时，在打字的过程中手会形成肌肉记忆，这些肌肉记忆导致打字时我们每个人的手指移动轨迹、打字力度、切换按键的节奏都各不相同。由此形成了类似“指纹”的个人特征，即使两个人打同一段文字，从时间序列上看也能看出明显差异。

三种关键的时间特征

Dwell Time（停留时间）

一个按键从按下到弹起的时间差：

1

dwell[i] = keyup[i].timestamp - keydown[i].timestamp

比如当我们按下h这个键，按下去到松手花了100ms，这100ms就是h的Dwell Time。有人习惯按的力度大一点（停留时间长），有人习惯按得轻一点（停留时间短），这就是在打字时个人习惯的体现。

DD Flight Time（Down-Down 间隔）

相邻两次按下之间的时间差：

1

dd[i] = down[i+1].timestamp - down[i].timestamp

这个时间特征反映了用户打字的整体节奏快慢，以及相邻字母之间切换的流畅程度。

UD Flight Time（Up-Down 间隔）

上一个键弹起到下一个键按下的时间差：

1

ud[i] = down[i+1].timestamp - up[i].timestamp

这个时间特征值有可能是负数——说明前一个键还没弹起，下一个键就已经按下了。UD比DD更能反映两键之间「重叠」的程度。

    // 退格键：同步撤销 keyEvents 中对应的记录
    if (e.key === "Backspace") {
        removeLastChar(keyEvents);
        return;
    }
    // 只记录可见字符，过滤 Shift、Ctrl 等功能键
    if (e.key.length === 1) {
        keyEvents.push({
            key:       e.key,
            action:    "down",
            timestamp: performance.now()  // 微秒级时间戳
        });

});
 
typeInput.addEventListener("keyup", function(e) {
    if (e.key.length === 1) {
        keyEvents.push({
            key:       e.key,
            action:    "up",
            timestamp: performance.now()
        });
    }
});

为什么用 performance.now() 而不是 Date.now()

Date.now() 精度只到毫秒级，而且受系统时间同步影响会跳变。performance.now() 是相对于页面加载的单调递增时间，精度到微秒级，更适合这种需要精确时间差的场景。

function removeLastChar(list) {
    // 从后往前找最后一个 down 事件
    let lastDownIdx = -1;
    for (let i = list.length - 1; i >= 0; i--) {
        if (list[i].action === "down") { lastDownIdx = i; break; }
    }
    if (lastDownIdx === -1) return;
 
    const lastKey = list[lastDownIdx].key;
    list.splice(lastDownIdx, 1);  // 删掉这个 down
 
    // 继续找对应的up也删掉
    for (let i = lastDownIdx; i < list.length; i++) {
        if (list[i].action === "up" && list[i].key === lastKey) {
            list.splice(i, 1);
            break;
        }
    }
}

TARGET     = "hello world"
TARGET_LEN = len(TARGET)  # 11

def extract_features(events):
    """
    从原始按键事件流提取 31 维特征向量。
    返回 numpy array，shape=(31,)；数据有问题时返回 None。
    """
    # 按顺序分离 down / up 序列
    down_seq = [(e['key'], e['timestamp']) for e in events if e['action'] == 'down']
    up_seq   = [(e['key'], e['timestamp']) for e in events if e['action'] == 'up']

    # 维度校验：两者数量都必须等于目标字符串长度
    if len(down_seq) != TARGET_LEN or len(up_seq) != TARGET_LEN:
        return None

    # ── Dwell Time ──────────────────────────────────────────
    # 关键：hello world 里 l 出现3次，o 出现2次，不能简单用下标对应
    # 必须按字符分组，再按出现顺序逐一匹配
    dwell_times = []
    for i, ch in enumerate(TARGET):
        d_list = [t for k, t in down_seq if k == ch]
        u_list = [t for k, t in up_seq   if k == ch]
        if i < len(d_list) and i < len(u_list):
            dwell_times.append(u_list[i] - d_list[i])
        else:
            dwell_times.append(0.0)  # 异常情况补零

    # ── DD Flight Time（Down-Down）───────────────────────────
    dd_times = [
        down_seq[i][1] - down_seq[i-1][1]
        for i in range(1, len(down_seq))
    ]

    # ── UD Flight Time（Up-Down）────────────────────────────
    ud_times = [
        down_seq[i][1] - up_seq[i-1][1]
        for i in range(1, len(up_seq))
    ]

    # 合并成 31 维向量
    return np.array(dwell_times + dd_times + ud_times)

第二阶段：距离计算

特征向量提取出来之后，认证时需要计算当前输入与该用户模板之间的相似度。相似度越高，说明越可能是同一个人。

下面介绍两种经典的距离计算方法：

1. 欧氏距离（Euclidean Distance）

欧氏距离是最直观的距离度量方式，相当于计算两点之间的直线距离。

公式：

$$ d_{欧氏}(x, y) = \sqrt{\sum_{i=1}^{n}(x_i - y_i)^2} $$

其中 $x_i$ 和 $y_i$ 分别是两个向量的第 $i$ 维特征值，$n$ 是特征维度总数（本项目 $n = 31$）。

直观理解： 把 31 维特征空间中的两个点，直接计算它们之间的"直线距离"。

优点： 计算简单，复杂度低 $O(n)$

缺点： 把 31 个维度平等对待，认为每个维度的贡献都一样。但实际上不同特征的稳定性差异很大——比如某些维度在不同次输入时波动很大（方差大），而有些维度非常稳定（方差小）。欧氏距离对这两种维度的"惩罚"是一样的，这不合理。

2. 马氏距离（Mahalanobis Distance）

马氏距离考虑了不同维度之间的相关性，以及各维度本身波动程度的差异。

公式：

$$ d_{马氏}(x, \mu) = \sqrt{(x - \mu)^T \Sigma^{-1} (x - \mu)} $$

其中：

  • $x$ 是当前输入的特征向量
  • $\mu$ 是该用户历史模板的均值向量
  • $\Sigma$ 是协方差矩阵，反映了各维度之间的相关性和各自的波动程度
  • $\Sigma^{-1}$ 是协方差矩阵的逆矩阵

计算步骤：

  1. 计算差值向量 $d = x - \mu$
  2. 计算协方差矩阵 $\Sigma = cov(X)$，$X$ 是历史样本矩阵
  3. 求协方差矩阵的逆 $\Sigma^{-1}$
  4. 代入公式计算 $d_{马氏} = \sqrt{d^T \Sigma^{-1} d}$

直观理解： 想象你在一张纸上画了一个椭圆形的靶心，靶心是 $\mu$。欧氏距离不管你往哪个方向射，只要离靶心的直线距离一样，就得分一样；而马氏距离会看你射的方向——如果是沿着椭圆长轴的方向（波动大的维度），即使离靶心稍远也不会被认为差距很大；如果是沿着短轴的方向（波动小的维度），稍微偏离靶心就会被认为是差很多。

为什么本项目选择马氏距离：

方差大的维度 → 在 $\Sigma^{-1}$ 里权重小 → 即使波动大也不"惩罚" 方差小的维度 → 在 $\Sigma^{-1}$ 里权重大 → 稍有波动就被"惩罚"

这就是马氏距离的自适应加权特性，让稳定的特征更重要，让不稳定的特征影响更小。

3. 两种距离的对比
欧氏距离 马氏距离
公式 $\sqrt{\sum(x_i-y_i)^2}$ $\sqrt{(x-\mu)^T\Sigma^{-1}(x-\mu)}$
复杂度 $O(n)$ $O(n^2)$ ~ $O(n^3)$
权重分配 所有维度平等 自适应分配
适用场景 各维度重要性一致 各维度重要性不同

本项目最终选择马氏距离，原因正如上表所示——击键特征中不同维度的稳定性差异很大，马氏距离能自动给稳定的特征更高权重。

def authenticate_user(user_id, feature_vector):
    # 加载模型文件
    scaler    = pickle.load(open(f'models/{user_id}_scaler.pkl',    'rb'))
    template  = pickle.load(open(f'models/{user_id}_template.pkl',  'rb'))
    cov_inv   = pickle.load(open(f'models/{user_id}_cov_inv.pkl',   'rb'))
    threshold = pickle.load(open(f'models/{user_id}_threshold.pkl', 'rb'))

    # 归一化新输入（用训练时保存的 scaler，只 transform 不重新 fit）
    new_vec_scaled = scaler.transform(feature_vector.reshape(1, -1))[0]

    # 计算马氏距离
    diff     = new_vec_scaled - template
    distance = float(np.sqrt(diff @ cov_inv @ diff))

    print(f"[auth] user={user_id}  distance={distance:.4f}  threshold={threshold:.4f}")

    passed = bool(distance < threshold)
    return passed, distance, threshold

踩坑记录

1、欧氏距离阈值怎么调都偏高

一开始我们用欧氏距离进行认证，固定阈值为3.5，结果测试时发现本人认证距离普遍偏高，阈值设3.5的认证成功率有点低，将阈值调的太高可能对部分用户来说又太松。调了很久都不满意，最后决定做一个自适应阈值。

根本原因： 归一化后，31维向量的欧氏距离理论期望值约为√31 ≈ 5.57，不是简单调调参数就能解决的问题。

解决方案： 换马氏距离然后改为自适应认证模式。马氏距离通过协方差矩阵的逆对各维度自动加权，消除了维度数量带来的基准偏高问题，认证成功率也提高了。

2、自适应阈值引入后，k值怎么调还是偏高

改完马氏距离，引入了threshold=mean+k*std的自适应阈值，但k改成得特别低阈值还是能高达7点多。

根本原因： 当时代码里用的还是欧氏距离计算历史距离分布，只是阈值公式换了，距离本身没换，所以mean和std还是基于欧氏距离的大数值，自然阈值也高。

解决方案： 必须保证构建模板时计算历史距离分布用的是马氏距离，和认证时用的方法是一致的：

总结

做得好的点： 用马氏距离能自动对稳定性高的特征加权，实际应用上比欧氏距离更合理；自适应阈值让每个用户有专属的判断边界，公平性更好；单用户异常检测方案逻辑上贴合真实认证场景。

不足之处： 目前只支持固定文本，随机性不足，安全性仍然较低；协方差矩阵对数据量要求较高（至少32条），采集数据需要花费较多时间；k值还是需要根据场景经验设定，并不是完全自动化。

后续可以改进的方向：

随机文本：每次认证随机发一个词，可以让攻击者录制的固定时间序列失效，可以有效抵挡重放攻击。但引入随机文本后，模板只能基于字符级别的统计，而不是固定文本的整体序列，算法复杂度会大幅提升。

交叉验证自动定 k：把历史数据逐条排除，用剩余数据建模板，对排除的那条计算距离，找到一个让所有样本都能通过的最小阈值，不需要手动调 k。
