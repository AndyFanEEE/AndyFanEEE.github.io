基于 VERITAS 的 Deepfake 检测最小复现：HydraFake 数据集与 ResNet18 baseline

Jul 05, 2026
阅读时长: 11 分钟

前言

这篇文章记录的是一次 Deepfake 检测论文的最小复现过程。项目基于 ICLR 2026 论文《VERITAS: Generalizable Deepfake Detection via Pattern-Aware Reasoning》，但目前并不是完整复现 VERITAS 的全部训练流程，而是先做一个 VERITAS-MINI 版本，把数据准备、baseline 训练和测试评估这条流程跑通。

一开始看到 VERITAS 这篇论文时，感觉它的切入点比较适合做复现：不是单纯追求某个数据集上的分类准确率，而是强调 Deepfake 检测在真实场景中的泛化能力。现实里伪造图片的来源会不断变化，今天是换脸，明天可能是扩散模型生成的人脸，再往后又可能是商业 App 一键生成的假身份头像。

不过完整 VERITAS 的成本比较高，涉及多模态大模型、SFT、MiPO、P-GRPO 等训练流程。对于一个课程项目或者入门复现来说，直接硬做完整版本并不现实。所以我先把目标缩小：基于 HydraFake 数据集做一个小型 real/fake 人脸图像检测任务，先训练 ResNet18 baseline，再准备 CLIP + Logistic Regression baseline。

项目概述

为什么做这个

Deepfake 检测本质上是判断一张图片或视频是否真实。这个问题现在越来越重要，因为 AI 生成人脸已经足够逼真，可以被用于虚假账号、诈骗头像、社交媒体身份伪装等场景。

传统图像分类任务通常只关心“训练集和测试集上准确率高不高”。但 Deepfake 检测更麻烦：模型在见过的伪造方式上表现好，不代表它能识别没见过的生成器。VERITAS 论文比较吸引我的地方就在这里，它强调的是 generalizable deepfake detection，也就是泛化能力。

简单说，这个项目想先回答一个小问题：

如果只用一个基础视觉模型，在 HydraFake 子集上做 real/fake 分类，能做到什么程度？

当前复现范围

完整 VERITAS 包括：

  • HydraFake 数据集构建
  • 多层次泛化评估
  • pattern-aware reasoning
  • SFT 监督微调
  • MiPO 偏好优化
  • P-GRPO 强化学习训练
  • 多模态大模型推理输出

这些内容都很重，尤其是后面的大模型训练部分。

所以当前项目先做 VERITAS-MINI 最小复现：

  • 使用 HydraFake val 子集
  • 构建 train / val / test 划分
  • 训练 ResNet18 二分类 baseline
  • 在 test split 上评估 Accuracy、Precision、Recall、F1 和混淆矩阵
  • 准备 CLIP image encoder + Logistic Regression baseline

目前已经完成 ResNet18 baseline 的训练和测试，CLIP baseline 脚本已经写好，但还没有正式跑出结果。

背景知识

Deepfake 检测到底在检测什么

在这个最小复现里，任务被简化成一个二分类问题：

1
2

real → 真实人脸图片
fake → AI 生成或伪造人脸图片

模型输入一张人脸图像，输出它更像 real 还是 fake。

这个任务看起来像普通图像分类，但它和猫狗分类不太一样。猫和狗的差异来自真实世界物体本身，而 Deepfake 检测很多时候是在找“伪造痕迹”。这些痕迹可能来自：

  • 皮肤纹理过于平滑
  • 面部边界不自然
  • 光照和阴影不一致
  • 背景细节异常
  • 生成模型留下的统计特征

问题是，不同生成模型留下的痕迹不一样。模型如果只记住某个数据集里的伪影，换一个生成器就可能失效。

VERITAS 论文的核心思路

VERITAS 论文主要解决两个问题。

第一个是数据和评估问题。论文提出 HydraFake 数据集，不只是简单收集 real/fake 图片，而是设计了更贴近真实部署的评估方式：

  • In-Domain：测试数据和训练数据来源相近
  • Cross-Model：测试 fake 来自没见过的生成模型
  • Cross-Forgery：测试 fake 来自没见过的伪造技术
  • Cross-Domain：测试数据进入更复杂的未知域

第二个是推理方式问题。VERITAS 不希望模型只输出一个真假标签，而是让多模态大模型按照更接近人工取证的方式推理。论文中的 pattern-aware reasoning 大致包含：

1
2
3
4
5
6

<fast>        快速初步判断
<planning>    规划要检查哪些线索
<reasoning>   基于图像证据分析
<reflection>  反思初始判断是否可靠
<conclusion>  综合证据给出结论
<answer>      输出 real 或 fake

这部分是 VERITAS 最有特色的地方。不过当前项目还没有进入多模态推理阶段，先从基础分类器做起。

为什么先不完整复现 VERITAS

完整 VERITAS 的门槛比较高。它不是简单训练一个 CNN，而是涉及多模态大模型训练和强化学习优化。当前环境也是 CPU 版 PyTorch，直接复现完整模型并不现实。

所以我把第一阶段目标定得很明确：

先不要追论文 SOTA 指标，先把最小可运行流程搭起来。

也就是先完成：

1

数据检查 → 数据划分 → ResNet18 训练 → test 评估 → 结果分析

这条链路跑通之后，后续再慢慢加入 CLIP baseline、跨域测试和 VERITAS-style prompt。

ResNet18 baseline 实现

模型设计

第一个 baseline 选择 ResNet18。原因很简单：它足够经典，训练速度比较可控，也适合作为图像分类任务的基础对照。

模型设置：

  • 使用 ImageNet 预训练 ResNet18
  • 替换最后的 fully connected layer
  • 输出类别数改为 2
  • fake = 0
  • real = 1

代码核心逻辑类似这样：

1
2
3
4
5

7
8

from torchvision import models
import torch.nn as nn

weights = models.ResNet18_Weights.IMAGENET1K_V1
model = models.resnet18(weights=weights)

in_features = model.fc.in_features
model.fc = nn.Linear(in_features, 2)

训练集损失从初始的 0.55 左右下降到 0.18，验证集损失在第 3 个 epoch 后有所波动但总体趋势下降。训练集准确率从 0.70 提升到接近 0.95，验证集准确率从 0.79 提升到 0.845。

对应的可视化热力图：

从结果看，ResNet18 在这个最小数据划分上是有效的。600 张测试图里预测正确 504 张，整体准确率是 84.0%。

fake 和 real 的识别也比较均衡：

  • fake 中有 250 张识别正确，50 张被误判为 real（假阴性）
  • real 中有 254 张识别正确，46 张被误判为 fake（假阳性）

两个方向的错误数量接近，没有出现明显偏向某一类的情况。从热力图可以看出，对角线上的数值较大（250 和 254），说明模型的分类能力比较稳定。

不过这个结果也不能看得太乐观。当前训练、验证、测试都来自 HydraFake val 子集的重新划分，数据来源比较接近。这说明模型在当前小数据集上学到了有用特征，但还不能说明它能应对真正的 Cross-Domain 场景。

换句话说，现在的 84.0% 是一个 baseline 起点，不是 VERITAS 论文里强调的泛化能力证明。

CLIP baseline 计划

为什么加入 CLIP

ResNet18 是传统 CNN baseline。它通过监督训练学习当前数据集里的 real/fake 差异，但也可能比较容易记住数据源特征。

所以后续我准备加入 CLIP baseline。CLIP 是大规模图文预训练模型，它的视觉编码器在很多任务上有比较好的迁移能力。这里不微调 CLIP，只把它当作 frozen feature extractor：

1

图片 → CLIP image encoder → embedding → Logistic Regression → real/fake

这样做的好处是训练成本低，尤其适合当前 CPU 环境。

当前实现方案

CLIP baseline 脚本已经创建并运行完成：

1

src/models/train_clip_logreg.py

使用的模型配置：

1
2

model_name = ViT-B-32
pretrained = laion2b_s34b_b79k

流程是：

  1. 使用 open_clip_torch 加载 CLIP
  2. 对 train / val / test 图片提取 image embedding
  3. 对 embedding 做 L2 normalize
  4. 用 train features 训练 LogisticRegression
  5. 在 val 和 test 上评估
  6. 输出指标、预测 CSV 和混淆矩阵

提取的特征被缓存在：

CLIP + Logistic Regression 测试结果

在测试集上的评估结果：

指标 数值
Accuracy 0.7383

Recall macro 0.7383
F1 macro 0.7383

混淆矩阵：

True \ Pred fake real
fake 219 81
real 76 224

对应的可视化热力图：

从结果看，CLIP + Logistic Regression 的准确率是 73.8%，低于 ResNet18 的 84.0%。

具体分析：

  • fake 中有 219 张识别正确，81 张被误判为 real（假阴性率约 27%）
  • real 中有 224 张识别正确，76 张被误判为 fake（假阳性率约 25%）

这个结果说明，在当前小数据集上，直接使用 CLIP frozen features + Logistic Regression 的效果不如微调 ResNet18。可能的原因有：

  1. CLIP 的视觉编码器虽然在大规模数据上预训练，但它没有针对 Deepfake 检测任务进行微调，提取的特征可能不够针对性。
  2. Logistic Regression 作为简单分类器，在特征空间中的决策边界可能不如深度神经网络灵活。
  3. 当前数据集规模较小（2800 张训练图），可能不足以让 CLIP 的迁移能力充分发挥。

不过这也是一个有意义的对照：它说明在小样本场景下，微调一个基础 CNN 可能比直接使用大规模预训练模型的 frozen features 更有效。

踩坑记录

坑一：完整 VERITAS 太重，不能一开始就硬复现

最开始看论文时，很容易被 VERITAS 的完整流程带着走：SFT、MiPO、P-GRPO、pattern-aware reasoning，看起来每个都很重要。

但实际做下来会发现，如果一开始就想完整复现，很可能会卡在数据规模、显存、大模型训练和标注数据构造上。对于课程项目来说，这样风险太高。

最后的处理方式是把目标拆开：

1
2
3

先做 VERITAS-MINI baseline
再做 CLIP 对比
后面再考虑 Cross-Domain 和 prompt 推理

这样每一步都有明确产出，也不会因为目标太大导致项目做不下去。

坑二：CPU 环境训练速度有限

当前 PyTorch 是 CPU 版本：

1
2

torch 2.12.1+cpu
torch.cuda.is_available() = False

这意味着不能像 GPU 环境那样随便加大 batch size 或训练很多 epoch。

所以 ResNet18 训练时只用了：

1
2

epochs = 5
batch_size = 16

CLIP 也不做微调，只提取 frozen embedding，再用 Logistic Regression 训练。这个方案虽然简单，但更适合当前环境。

坑三：ImageFolder 的类别顺序必须确认

torchvision.datasets.ImageFolder 会按照文件夹名字排序生成类别编号。当前目录是：

1
2

fake/
real/

所以得到：

1

{'fake': 0, 'real': 1}

这个顺序看似小事，但如果后面画混淆矩阵或者保存预测 CSV 时搞反，整篇实验分析都会错。

因此训练脚本和评估脚本都打印并保存 class_to_idx。这也是复现实验中很值得保留的一个小习惯。

坑四：当前测试不是跨域测试

ResNet18 的 test accuracy 是 84.0%，看起来还不错。但这里的 test split 来自同一个 HydraFake val 子集的重新划分。

这和 VERITAS 论文里真正关心的 Cross-Model、Cross-Forgery、Cross-Domain 还不是一回事。

所以当前结果应该这样理解：

1

ResNet18 在当前最小划分上可以作为有效 baseline。

而不能理解成：

1

ResNet18 已经具备很好的 Deepfake 泛化检测能力。

后续如果要更贴近论文，需要下载 test/id.zip 和 test/cd.zip，做 In-Domain vs Cross-Domain 对比。

总结与展望

总结

做得还行的地方：

这次最小复现已经跑通了两条完整流程：

  1. ResNet18 baseline：数据检查 → 数据划分 → ResNet18 微调 → test 评估 → 结果保存。在 600 张测试图片上取得了 84.0% 的准确率。

  2. CLIP + Logistic Regression baseline：CLIP 特征提取 → L2 归一化 → Logistic Regression 训练 → test 评估。在 600 张测试图片上取得了 73.8% 的准确率。

两个 baseline 的对比结果如下：

不足之处

目前不足也很明显：

当前只使用 HydraFake val 子集，没有覆盖完整 HydraFake 的分层测试协议。ResNet18 的结果只能说明它在当前小规模划分上有效，不能说明它面对未知生成器或未知伪造方式时仍然可靠。

另外，训练准确率高于验证和测试准确率，说明模型存在一定过拟合趋势。这个问题后续需要通过 CLIP baseline 和跨域测试进一步观察。

后续计划

后续准备继续做三件事：

第一，运行 CLIP + Logistic Regression baseline，看看大规模预训练图像特征在这个任务上是否比 ResNet18 更稳。

第二，下载 HydraFake 的 test/id.zip 和 test/cd.zip，做 In-Domain 和 Cross-Domain 对比。这个阶段会更接近 VERITAS 论文真正关心的问题。

第三，尝试 VERITAS-style pattern-aware prompt。也就是不训练大模型，而是调用多模态模型，让它按照：
